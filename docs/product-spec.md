# DeepSeek GenUI — MVP v0.1.1 产品规格

状态：产品方向已确认；阶段 1–5 的本地实现已完成，阶段 4 真实会话单案例手工复核已完成，阶段 5 三个组合场景已提供本地测试样例；阶段 6–8（完整操作体验、默认真实模型验收、发布）尚未完成。合成样例和本地测试不能替代真实模型验收。
确认日期：2026-11-01。

## 1. 产品定位

让 DeepSeek 根据用户的问题，在官方网页版的回答中生成一个可以直接使用的小工具。

产品体验向用户期待的 ChatGPT 交互方式靠拢：用户能够在回答内调整条件、探索变化、完成比较或计算，并继续围绕结果讨论。界面根据问题组织，整体视觉统一。

## 2. 已确认的产品决策

- 第一版同时覆盖学习中的交互演示，以及比较、计算、规划工具。
- 默认引导 DeepSeek 在适合的场景生成交互界面；普通问题继续正常回答。
- 用户可以明确要求生成交互界面，也可以关闭增强。
- 界面直接嵌在回答的对应位置，前后普通文字保持 DeepSeek 原生呈现。
- 复杂界面可以展开查看。
- 调整参数、筛选条件或修改输入后，相关图形、数值和结果即时更新。
- 界面形态根据问题组合，不限于固定的图表、表格、卡片布局。
- 图表、表格、卡片是基础展示能力；滑块、输入框、选择器等是必要的操作能力。
- 操作本身不发送聊天消息。用户可以主动把当前条件和结果带入后续对话。
- 提供重置操作，允许用户回到该界面的初始状态。

## 3. 核心使用流程

1. 用户在 DeepSeek 官方网页版正常提问。
2. 在增强开启且适合交互的情况下，DeepSeek 输出解释和交互界面描述。
3. 扩展在回答原位置呈现界面。
4. 用户在界面内操作，直接看到相关结果变化，不需要为每次操作重新提问。
5. 用户需要进一步讨论时，主动选择将当前条件和结果带入输入框，检查后自行发送。

默认自动生成是产品行为目标。提示词增强应当可见、可控制；实际进入对话的增强内容必须能被用户查看。不能以隐藏注入或自动发送来达成默认体验。

## 4. 三个首版验收场景

这些场景用于验证通用能力，不应实现为只能响应固定问题的三个页面。

### 4.1 学习：抛物线演示

示例提问：帮我用交互演示理解二次函数各个参数的作用。

- 用户调整 a、b、c，曲线、函数表达式及相关数值同步变化。
- 根据当前参数解释开口方向、顶点等相关性质。
- a 为 0 时正确说明退化情况，不显示无效顶点或崩溃。
- 用户可以重置参数，并展开查看演示。

### 4.2 决策：选购比较

示例提问：根据我提供的三款笔记本资料，做一个可以调整预算和偏好的比较工具。

- 用户调整预算、偏好或筛选条件，候选结果与排名同步更新。
- 展示排名依据和所用数据，能够理解偏好调整产生的影响。
- 缺少价格或性能资料时说明缺失，使用用户提供的数据或明确标注的示例数据。
- 没有符合条件的选项时显示有用的空状态。

### 4.3 工具：预算规划

示例提问：做一个每月预算分配工具，让我调整各项支出并看到余额。

- 用户修改总预算和各项分配，合计、余额与图表同步变化。
- 超支、空输入、零预算等情况有明确且正确的反馈。
- 不静默修改用户输入来制造收支平衡。
- 用户可以重置，并把当前分配结果带入后续讨论。

## 5. 体验要求

- 控件有清楚的名称、当前值和必要的单位。
- 图形、数值和解释使用同一份当前状态，不能相互矛盾。
- 数据来源、假设与示例数据应清楚标注；不为了完成界面编造事实。
- 界面适配亮色与暗色主题及常见桌面窗口尺寸，操作支持键盘。
- 生成过程中优先保持稳定，避免展示尚未完整的界面。
- 解析或渲染失败时，原始内容仍可查看，用户可以继续正常聊天。
- 不应干扰原页面的输入、滚动、复制、会话切换等功能。

## 6. MVP 边界

首版围绕本地交互、计算、筛选及可视化展开。复杂小游戏、任意完整应用、实时价格查询、外部账户连接、云同步、多网站支持及完整 Agent 工具调用留待后续版本。

v5 起，预算、成本比较与偏好比较中规则明确的计算由本地 `models` 承担；模型负责选择数据、约束与呈现方式。该能力降低转录与逻辑拼接错误，但不证明模型提供的价格等外部事实正确，发行说明需写明解释范围与内置规则。

普通 Markdown 不自动转换；只有明确的 GenUI 内容才增强。模型输出不能直接执行任意代码，也不能控制网络请求、浏览器权限或本地文件。

首版支持同一页面内的状态保持，以及用户主动「保存方案」后的本机刷新恢复；不承诺跨设备共享、云同步或导出独立应用。恢复按会话、消息与原始文档哈希区分身份，身份不可靠时只做页面内恢复并拒绝写本机；文档改写、状态结构或取值域变化时不套用旧状态。详见[状态保存与恢复](state-storage.md)。真实页面上的恢复行为仍需持续复核并如实说明。

## 7. 完成标准

三类场景均能从实际问题生成适合的界面，并完成有效操作。用户能够通过操作探索问题或完成任务，普通聊天仍保持正常。
