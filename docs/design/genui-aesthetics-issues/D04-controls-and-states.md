# D04：统一输入控件与交互状态的视觉表现

状态：已发布，待开发。

GitHub：[#14](https://github.com/realhenrylan/chat-deepseek-genui/issues/14)。

## 问题与用户影响

数值输入、选择器、滑块、提示及错误信息已经具备功能，但尚缺统一的尺寸、状态和标签组织规则。界面有多个参数时，当前值、单位和编辑反馈需要更容易辨识。

## 设计目标

用户容易看懂可以改什么、当前选了什么、操作是否有效，并能快速修正输入错误。

## 已确认的设计方向

- 保持简洁系统感、统一造型，与 DeepSeek 对话协调。
- 滑块当前值与参数标签同排，单位与数值关系明确。
- 延续少装饰、适中密度的共同基调。

以上来自用户第一、二轮选择。说明、错误、焦点和反馈的具体视觉规格在上述方向内制定，保证区分明确与可读性。

## 验收方向

- 同类型控件在不同示例中形态一致。
- 当前值、单位、可编辑区域和焦点位置清楚。
- 无效输入能就近解释原因，并提供可理解的修正方向。
- 亮/暗主题、键盘操作和窄栏下均保持可读与可操作。

## 范围与协作

依赖 D01 和 D02；提示内容与其他说明的层级需保持一致。

## 技术方案

- 继续使用语义化原生 `input[type=number]`、`input[type=range]` 和 select，在 Shadow DOM 内用 D01 变量统一尺寸、边界、焦点和背景；不引入自定义下拉弹层、Portal 或新组件库。
- 调整 `interactive.tsx`：滑块使用“标签 + 当前 output”的顶行，range 独占下一行；保留真实 label/htmlFor、output 关联、aria-valuetext、aria-describedby 与 aria-invalid，避免对同一当前值重复播报。
- 默认控件最小高度约 36px，触屏环境目标约 44px；窄栏标签和值允许合理换行。数字使用统一格式化和等宽数字，单位随值一起呈现。
- 普通控件、悬停、焦点、当前选择、不可用和错误状态复用有限的样式角色；DeepSeek 蓝用于主交互/焦点，灰阶区分层次，错误以文字和必要状态色共同表达。不可用状态仅在业务确有需要时出现，不为视觉演示禁用现有功能。
- 复用既有草稿、已提交数值、步长校验与错误展示逻辑；轻微过渡仅作用于颜色/边界，不对拖动中的数字和曲线增加延迟动画，尊重减少动态效果偏好。

## 实现与验收

- [ ] 鼠标和键盘调整 range、编辑 number、操作 select 均保持原有数值边界和提交语义。
- [ ] 空值、非法值、越界、步长不齐和输入法场景仍显示就近错误，最后有效值继续用于计算。
- [ ] 标签、当前值和单位在长中文及窄栏下清楚；焦点可见且不会落到不可见元素。
- [ ] 亮暗主题均有一致的交互状态，错误不只依赖红色区分。
- [ ] 同参数的多个绑定控件与多个卡片仍同步正确、彼此隔离；运行相应交互单测及 Edge/Chrome e2e。
