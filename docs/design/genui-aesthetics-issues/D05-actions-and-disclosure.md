# D05：梳理卡片操作与辅助信息的呈现层级

状态：已发布，待开发。

GitHub：[#15](https://github.com/realhenrylan/chat-deepseek-genui/issues/15)。

## 问题与用户影响

页脚同时展示“重置当前界面”“继续讨论”“查看原始 JSON”，视觉权重接近，还带有较长的技术说明。页头还有标识、标题和展开/收起操作。

使用者需要识别下一步行动，偶尔查看数据或原始内容的人也需要找得到对应入口。

## 设计目标

让常用操作容易发现，辅助操作位置稳定，原始内容与说明保持可访问；减少操作栏对主要内容的干扰。

## 已确认的设计方向

- “继续讨论”保留直接可见入口。
- 重置保持可访问，视觉权重较轻。
- 原始 JSON 和技术说明收进辅助详情区域，按需展开。
- 按主次呈现操作，延续轻边界、少装饰的共同基调。

以上来自用户第二轮选择。页头标识与展开/收起入口在整体基调内保持清楚、克制，具体规格由 Codex 制定。

## 验收方向

- 用户能区分直接操作、继续对话和查看原始内容的入口。
- 重置和原始内容查看仍容易找到，文字说明清楚。
- 窄栏换行后仍保留稳定的操作顺序与层级。
- 继续讨论仍先把内容带入输入框，由用户决定是否发送。

## 范围与协作

依赖 D01；与 D03 一起控制头部、内容区和页脚的空间关系。

## 技术方案

- 在 `Card.tsx` 中保留直接可见的“继续讨论”，重置采用较轻的按钮外观；原始 JSON 切换与插件技术说明放入原生 details/summary 的“界面详情”区域，默认收起。
- 技术说明指“透明增强、原始字符数、执行边界”等插件元信息；来源、示例标记、影响结果的假设、输入错误和必要风险提示不移入该区域。
- 继续复用 `onContinue`、`buildContinueSummary`、`onToggleRaw`、现有 followup 反馈及重置逻辑，不重写摘要内容，不自动发送，不增加确认弹窗。
- details 的开合属于本地视图状态，操作不卸载 Card；显示原始代码块时卡片与“收起原始 JSON”入口仍可访问。主卡收起后隐藏的控件不得进入 Tab 顺序，重新展开保留已调整值和必要详情状态。
- 使用现有品牌标识并降低重复 badge 的视觉权重；展开/收起入口保持明确的文本或可访问名称。反馈显示在触发操作附近，沿用 role=status，不把失败提示藏入详情。

## 实现与验收

- [ ] 继续讨论和轻量重置可直接发现，详情可通过键盘打开并查看原始 JSON。
- [ ] 切换原始 JSON 后能返回；卡片参数、筛选/排序和当前结果不因查看详情而丢失。
- [ ] 已有草稿逐字保留、不自动发送；无输入框、不可用回调、重复点击均保持既有确定行为。
- [ ] 重置仍清除本地输入错误并恢复表格初始筛选/排序语义。
- [ ] 亮暗主题和窄栏换行后操作顺序稳定；关键来源、假设、错误和风险默认可见。
- [ ] 覆盖 v1 无继续讨论/重置以及 v2/v3 的完整操作路径，验证原始内容回退。
