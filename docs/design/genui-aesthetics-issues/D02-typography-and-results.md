# D02：建立文字与关键数值的信息层级

状态：已实现（2026-11-05），待发布验收。

GitHub：[#12](https://github.com/realhenrylan/chat-deepseek-genui/issues/12)。

## 问题与用户影响

当前卡片标题与正文均为 14px，区域标题为 13px；主要通过字重区分。value 常用一行标签和值表达，各数值视觉权重接近。

用户打开预算、成本或学习界面时，不容易立刻识别核心结果、可调参数和解释之间的关系。

## 设计目标

用户扫视标题、标签与数值，就能理解界面的用途和主要结果。单位、假设及辅助说明保持清楚，同时让关键内容有稳定的阅读优先级。

## 已确认的设计方向

- 适度突出一至两个主要结果，其余数值较安静。
- 核心内容清楚，细节按需展开，整体密度适中。

主次主要通过字号、字重、位置与留白体现，配色遵循默认黑白和 DeepSeek 蓝；说明披露与 D03、D05、D06 一致。

## 验收方向

- 预算中的主要结果、选购中的主要比较信息、函数学习中的重要数值容易识别。
- 数字、单位、正负号及长中文标签的关系明确，变化时不发生明显跳动。
- 主次区分不依赖颜色这一种方式，长文本和文字缩放后仍可读。
- 模型生成的内容顺序与本地组件样式对重点的表达一致。

## 范围与协作

依赖 D01 的视觉基调；与 D03 的布局共同决定信息组织。

## 技术方案

- 在 D01 的变量体系内建立标题、区域标题、正文、辅助文字和主要结果角色；初始规格为标题 16px、正文 14px、辅助文字 12–13px、主要结果 20px，保留字体缩放能力，结合截图验证微调。
- 在 **v3–v5 的 value 元素**新增可选 `emphasis: "normal" | "primary"`（协议主线已升级到 v5，按 issue 约定合并到同一策略）。省略时为 normal，不根据标签文字、数值大小或派生变量顺序猜测业务重要性。文档顺序中前两个显式 primary 获得强调；超出的 primary 按普通结果呈现，保留其内容和计算，不因纯展示数量让整卡失败。
- v3–v5 Schema、TypeScript 类型和渲染入口明确特化该字段，不扩展 v1/v2 的允许字段。同步 `schema.ts`、`types.ts`、`validate.ts`（如需）、生成校验器和协议文档。新扩展继续读取旧 v3–v5 文档；旧扩展无法读取新字段时按既有机制保留原始 JSON，不声称双向兼容。
- `interactive.tsx` 将数字与单位分为可单独排版的内容，同时保留完整可访问文本、现有格式化与单位回退；使用等宽数字改善变化时对齐。主结果的错误信息就地显示，不能把无效结果显示成 0。
- 用路径稳定的展示上下文计算强调资格，不新增业务 state；沿用同一计算快照。同步示例和可见提示词，升级提示词版本并说明该能力，不把尚未支持的字段提前写入说明。
