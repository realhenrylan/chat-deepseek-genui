# 阶段 9：v5 语义模型的首轮可用性对比

更新日期：2026-11-04。对应 issue #4「可组合语义能力」。本报告只比较**协议描述方式**对模型生成结果的影响，不评估价格、参数等事实是否真实。

## 方法

- 任务：预算小工具（收入 12000，房租 4500、餐饮 2600、交通 600、其他 900；餐饮/其他可调）与笔记本偏好比较（4 个候选、价格/重量/续航、权重 40/30/30、预算与重量筛选、D 缺续航）。
- 对照组：v2.3 提示词（协议 v4，模型手写 state/derived/表格/图表表达式）。
- 实验组：v2.4/v2.5 提示词（协议 v5，模型只声明 `models`，元素读取同一快照）。
- 每个「任务 × 提示词」采样 2 次；v5 预算额外重采样 1 次以验证键名修正，共 9 份输出。
- 输出由同一模型（DeepSeek 子代理）生成，经 `parseGenui` 解析、`evaluateComposite` 求值并挂载到 JSDOM 卡片；记录 JSON 字符数、解析错误、元素/derived/models 数量、运算次数与关键业务值。
- 局限：样本量小，同一模型家族，非生产 API/真实用户；v5 提示词在采样过程中从 v2.4 修正到 v2.5，部分失败已通过协议容错解决。结论只用于方向判断，不作统计显著性声明。

按 v5 定义复算：A 51.0、B 40.0、C 60.0、D 60.286（只对已知维度归一，缺失续航不进分母）。v4 两份输出对 D 的处理不同：一份给区间并标「名次待定」，另一份折算 60.3 后直接排第一；这不是计算错误，而是同一业务问题采用了不同规则，正好说明「规则下沉到受测实现」的必要性。

### 汇总

- 首轮解析：v4 4/4；v5 在协议容错前 2/5（预算 1、偏好 2），容错后 4/5。剩余失败是 v2.4 提示词未列固定标量键，v2.5 已补。
- 输出长度：预算 v5 平均 2216.5 字符，v4 平均 6376.5 字符（约 −65%）；偏好 v5 平均 5613.5，v4 平均 12708.5（约 −56%）。v5 全部样本平均约 3632 字符，v4 约 9542 字符（约 −62%）。
- 计算一致性：v5 预算/偏好均 0 derived、0–7 次运算，数值/表格/图表/解释读同一模型快照；v4 需要 5–18 个 derived、46–174 次运算，且偏好的缺失值规则因样本而异。
- 可解释性：v5 的 `explain` 与 `basis`/`diagnostics` 明确说明归一、权重、缺失和并列；v4 的解释散落在模型手写文本中，无法保证与计算一致。
- 失败模式：v5 主要集中在固定键名（`ratio` vs `usage`）与 source 形状；已通过固定标量键、filters 数字常量、可选 `kind:"model"` 降低首轮失败率。v4 的主要风险是长表达式链和缺失值规则不一致。

## 结论

在本次小样本中，v5 用更短的描述显著减少了手写派生与运算，并让参数、数值、表格、图表和解释共享同一计算快照；代价是模型需要熟悉固定标量键与少量 source 形状。v4 在本样本中首轮解析更稳，但输出更长，偏好任务出现两种不同的缺失值处理规则。后续应扩大样本、固定提示词版本，并覆盖零预算、零次数、空候选和并列的生成成功率。

原始输出为临时文件，未纳入仓库；上表数字来自 `tests/unit/benchmark-issue4.test.ts` 的实测运行。
