# 卡片状态保存与恢复

本文说明交互卡片的状态在页面内如何保持、`保存方案` 会写入什么，以及刷新、重新挂载、文档改写和切换会话时的恢复与重置规则。实现对应 issue #2 与 issue #6（方案工作台），相关代码在 `src/runtime/card-state.ts`、`src/runtime/scenario.ts`、`src/runtime/csv.ts`、`src/content/identity.ts`、`src/content/plan-store.ts`、`src/content/scenario-store.ts`、`src/content/enhance.ts`、`src/render/Card.tsx` 与 `src/render/scenario-panel.tsx`。

## 一句话结论

- 页面内：调整过的参数、表格筛选与排序自动保存在当前标签页内存中，生成新回答、同一文档的节点替换或重新挂载不会回到初始值。
- 刷新后：默认不恢复；只有你点击卡片上的 **保存方案**，必要的状态字段才会写入本机 `chrome.storage.local`，下次打开同一会话、同一消息、同一文档时恢复。
- 跨会话/跨消息：不会串用。身份不可靠时只做页面内恢复，并拒绝写入本机。
- 保存方案不会让模型知道你当前的选择；需要把条件带回对话时，使用「继续讨论」生成的摘要并自行发送。

## 两层状态

| 层 | 触发 | 存放位置 | 生命周期 |
| --- | --- | --- | --- |
| 页面内状态 | 调整参数、筛选、排序时自动写入 | 内容脚本内存（每个会话最多 200 张卡片，按最近使用淘汰） | 当前标签页；刷新或关闭页面即丢失 |
| 保存的方案 | 仅点击「保存方案」时写入 | `chrome.storage.local`，每个方案一个键 | 直到你点击「清除保存」、卸载扩展，或超出容量被清理 |

页面内状态优先于保存的方案：刷新后首次渲染会先查找保存记录，之后的所有调整只更新内存；要更新本机记录必须再次点击「保存方案」（按钮会显示「更新保存的方案」）。

## 身份：怎么判断「还是同一张卡片」

状态键由五段组成，不按标题或 DOM 顺序匹配：

```
card|<状态结构版本>|<账号作用域>|<会话路由>|<消息键>|<同文档重复序号>|<原始文档哈希>
```

- **账号作用域**：读取站点提供的 `data-user-id` / `data-account-id` / `meta[name="user-id"]` 等稳定标记，哈希后使用；缺失时为 `acct-unknown`，此时仍可按会话作用域保存，但不声称账号级隔离。原始账号 id 不会写入键或保存记录。
- **会话**：只接受 `/a/chat/s/<会话 id>` 形式的路由，去掉末尾斜杠；其他路由一律视为 `unknown-session`。
- **消息**：优先取最近的 `data-virtual-list-item-key`，其次 `data-message-id`；两者都没有时退化为消息文本指纹（不可靠）。
- **重复序号**：仍记录同一消息内的出现次序，但一旦出现完全相同的文档，该序号不再参与区分（见下）。
- **文档哈希**：原始 genui JSON 文本的哈希。原文一旦变化就得到新键，旧状态不会被套用到新文档。

两种安全状态分开处理：

- **消息/文档身份有歧义**：只有文本指纹、同一消息键被多个消息共用、或同一消息内出现完全相同的文档。此时这些卡片不再共享状态键，改为按 DOM 元素分配一次性键（`amb|<元素令牌>|<文档哈希>`）。同一元素跨扫描保持稳定，但节点替换后即失效；宁可丢失状态，也不让相邻卡片串值。
- **不可持久化**：会话路由无法确认，或身份有歧义。此时页面内恢复仍可用，但拒绝写入本机保存，并提示「当前会话或消息身份无法可靠确认，未保存到本机」；保存记录的读取同样跳过这类身份。

只有会话可验证且身份无歧义时，保存记录才允许写入与读取；账号标记存在时再叠加账号作用域。

## 兼容、迁移与重置

| 变化 | 行为 |
| --- | --- |
| 同一文档的节点替换、虚拟列表回收后重新挂载 | 身份无歧义时恢复参数、表格筛选与排序；身份有歧义时为元素级键，重新挂载后回到初始值 |
| 原始代码块被改写（哪怕标题相同） | 文档哈希变化 → 新身份；旧内存状态删除，按新文档初始值挂载 |
| 状态结构版本升级 | 旧保存记录不再兼容，不应用；按新文档初始值挂载 |
| 状态变量类型、取值域、步长、选项变化 | `stateSignature` 不一致，保存记录不应用 |
| 保存记录中的值越界、不符合步长或已不在选项中 | 逐项清洗：回落到该字段初始值，其余合法字段保留 |
| 表格列变化、排序列不再存在 | 丢弃该排序，筛选文本保留并重新过滤 |
| 切换账号、会话、消息或相同标题 | 账号标记存在时作用域不同；缺失时依赖会话路由与消息键隔离，互不串值。账号无法确认时仍可保存，但不做账号级保证 |

没有自动迁移：不兼容的旧记录不会强行套用，也不会删除；它们不会被另一份文档使用，并会在容量清理时按保存时间从旧到新淘汰。

## 保存记录里有什么

每个方案一条 `chrome.storage.local` 记录，键为 `genuiPlan:<卡片身份>`，内容仅包含恢复所必需的数据：

- 状态结构版本、文档哈希、状态定义签名；
- 账号作用域哈希（不可逆，不含原始账号 id）、会话路由、消息键、同文档重复序号、保存时间；
- 各状态变量的当前值（数字或选项值）；
- 每张表格的筛选文本与排序列/方向。

不保存聊天正文、AI 回复全文、标题、用户草稿或原始账号信息，也不发起网络请求或云同步。保存上限为 50 条；单条记录超过 32 KiB 或存储配额不足时会返回明确的失败提示，页面内状态不受影响。容量清理旧记录失败时，本次新记录仍视为保存成功，`evicted` 只报告实际删除的数量，旧记录会在下一次保存时继续清理。

## 操作与反馈

- **保存方案**：写入或更新当前卡片的本机记录；成功提示「已保存到本机，刷新后可恢复。」，若因容量清理了旧记录会补充清理数量。
- **清除保存**：只删除当前卡片的本机记录，内存中的当前调整保持不变；成功提示「已清除本机保存的方案。」。
- **重置当前界面**：恢复初始参数并清空筛选，回到初始排序；不会自动删除已保存的方案。
- 存储不可用（例如无 `storage` 权限的测试环境）时不显示保存入口；保存/清除失败会在卡片底部以 `role="status"` 文案说明原因。

## 方案工作台（issue #6）

卡片正文底部提供「方案工作台」面板，把「探索一次参数变化」扩展为「保存多个方案 → 并排比较 → 选择 → 导出或继续讨论」。方案是**用户主动命名的本地快照**，与上面的「保存方案」（单卡自动恢复点）分开存放：

| 项 | 说明 |
| --- | --- |
| 存储键 | `genuiScenario:<方案 id>`，`chrome.storage.local`，与 `genuiPlan:` 前缀互不干扰 |
| 容量 | 最多 50 条，超出按保存时间淘汰最旧；单条超过 48 KiB 拒绝保存 |
| 内容 | 方案名、保存时间、文档哈希、状态签名、协议版本、计算规则版本、资料依据（会话/消息/标题）、当时的参数、表格视图与结果快照 |
| 不含 | 聊天正文、AI 回复全文、用户草稿、账号信息；不发起网络请求或云同步 |

**保存与比较**：

- 在名称框输入后点击「保存当前方案」，当前参数与结果按当时的状态固化；保存 A 后继续调整 B 不会覆盖 A 的输入与结果。
- 勾选两份方案后「并排比较」逐项列出参数与结果差异（数值项附 `b - a` 差值），变化行高亮。
- 仅当两份方案的文档哈希、状态签名、协议版本与计算规则版本全部一致时才给出比较；任一不兼容会明确列出理由（如「状态字段定义不同（取值域或选项已变化），无法比较。」），不输出误导性对比。

**导出与导入**：

- 每份方案可导出为 JSON（原始快照）或可读摘要（`buildScenarioSummary` 纯文本，与「继续讨论」交接格式一致）；两方案差异可导出为差异摘要。表格数据可导出 CSV：表头并入单位、单元格按当前状态求值、行可见性过滤，分隔符/引号/换行按 RFC 4180 转义，`=`、`+`、`-`、`@` 开头的不可信单元格加单引号前缀防止表格软件当作公式执行。
- 导入先校验：文件大小（64 KiB）、JSON 可解析性、`format: "genui-scenario"` 标记、版本是否受支持、字段完整性、单条大小，以及文档哈希/协议/状态签名是否属于当前卡片；只解析 JSON，不执行导入内容中的任何代码；已存在同 id 的方案不会被覆盖（提示「未覆盖；如需替换请先删除原方案」）。旧格式、损坏文件、超大文件与不支持版本都有明确文案反馈。

**保存时结果 vs 按当前规则重算**：

- 每份方案保存当时的派生结果快照，并记录计算规则版本；列表项在按当前文档重算结果与保存不一致时显示「按当前规则重算与保存时不一致」标记（规则或数据已变化的提示），差异详情以保存值为准展示，不悄悄改写历史值。

**删除与清理**：

- 单条「删除」与「清除全部方案」都会立即移除本机对应键（与隐私说明同步）；容量上限同时防止方案无限增长。

**交给继续讨论**：

- 「继续讨论此方案」把该方案的可读摘要、「差异交给继续讨论」把两方案差异摘要交给「继续讨论」流程（与卡片页脚同一回调），由挂载方填入聊天输入框，绝不自动发送。

## 边界与已知限制

- 页面内状态只存在于当前标签页，刷新、关闭标签页或卸载扩展后消失；跨设备不同步。
- 刷新恢复依赖站点提供稳定的消息标记（`data-virtual-list-item-key` 或 `data-message-id`）与可识别的会话路由；账号标记缺失时按 `acct-unknown` 作用域保存并正常恢复，不阻断功能。这需要在真实页面复核。
- 账号标记缺失时，同一会话路由在另一个账号打开理论上可能读取到该方案；当前站点没有可验证的账号标记，因此以会话路由作为主要隔离边界，不宣称跨账号绝对隔离。
- 同一消息内出现完全相同的文档，或两条消息共用同一消息键时，身份转为元素级：宁可重新挂载后回到初始值，也不共享状态。
- 保存方案只恢复界面状态，不改变对话上下文；模型不会自动知道当前选择。
- 同一卡片被改写后，旧的保存记录不会被新文档使用；它可能在容量上限内暂时保留，直到被覆盖或随容量清理淘汰。
- 清除入口针对当前卡片；其他会话或已被删除消息的保存记录只能等容量清理，或卸载扩展时一并清除。
