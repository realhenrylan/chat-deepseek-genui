# 卡片状态保持与恢复

本文说明交互卡片的状态在页面内如何保持，以及用户主动保存后如何在本机恢复。实现对应 issue #2（收尾）与 issue #10 第一阶段，相关代码在 `src/runtime/card-state.ts`、`src/runtime/card-state-store.ts`、`src/runtime/saved-card-state-store.ts`、`src/content/identity.ts`、`src/content/enhance.ts`、`src/content/controller.ts` 与 `src/render/Card.tsx`。

2026-11-04 起移除了手动「保存方案」、`genui-plan` 方案文件与「方案工作台」；本文件只描述卡片自身的状态保持与本机保存。方案快照、并排比较与导入导出（issue #6）不属于本文范围。

## 一句话结论

- 页面内：调整过的参数、表格筛选与排序自动保存在当前标签页内存中，生成新回答、同一文档的节点替换或重新挂载不会回到初始值。
- 本机保存：只有用户点击「保存当前界面」时，才把这一张卡片的参数、筛选与排序写入 `chrome.storage.local`；刷新后同一文档自动恢复，并在卡片内标明恢复时间。
- 未保存的调整不会跨刷新保留；恢复后继续调整不会自动覆写本机记录，需要再次点击「更新已保存的设置」。
- 跨会话/跨消息：不会串用；身份有歧义时退化为元素级一次性键，既不恢复也不提供保存。
- 状态保持与保存都不会让模型知道你当前的选择；需要把条件带回对话时，使用「继续讨论」生成的摘要并自行发送。

## 状态层

| 层 | 触发 | 存放位置 | 生命周期 |
| --- | --- | --- | --- |
| 页面内状态 | 调整参数、筛选、排序时自动写入 | 内容脚本内存（每个标签页最多 200 张卡片，按最近使用淘汰，`MAX_IN_MEMORY_CARD_STATES = 200`） | 当前标签页；刷新或关闭页面即丢失 |
| 主动保存的设置 | 用户点击「保存当前界面」或「更新已保存的设置」 | `chrome.storage.local`，键为 `genuiSavedState:<卡片键>`，一条记录一个 storage 键 | 直到用户清除、被容量淘汰或卸载扩展；不同步、不上传 |

两层互不替代：页面内状态负责同一页内的节点替换与重新挂载；本机保存负责刷新或重新打开页面后的恢复。清除本机保存不会改变当前界面上的值，重置当前界面也不会删除本机保存。

另有一个与卡片状态无关的本地诊断记录器（`src/runtime/diagnostics.ts`，schema `genui-diagnostics/v1`）：只保存固定类别/代码的计数与首次、最近时间，以及适配器探针的计数与布尔值，仅存在于当前页面内存，随标签页关闭消失，不写入 `chrome.storage.local`，也不参与卡片身份或状态恢复。用户主动打开「本地诊断」时才会生成预览，详见 [隐私说明](privacy.md)。

## 历史与气泡剥离（不保存状态）

历史响应与用户气泡里的协议不写入任何存储，也不建立消息索引；每次读取时按内容即时判断：

| 项 | 说明 |
| --- | --- |
| 触发 | 站点读取历史消息（`GET /api/v0/chat/history_messages`）时清洗用户角色正文与 `fragments` 中的 `REQUEST` 片段；页面扫描到 `.ds-message` 用户气泡时清洗其文本尾部 |
| 判定 | 仅当尾部与内置已知版本（v4.0/v3.2/v3.1/v3.0，自动/工具版）的完整协议正文逐字相等（忽略空白差异），或尾部是首尾标记完整且内部 FNV-1a 校验码与正文匹配的修复详情块时，才移除该段；实现见 `src/content/prompt.ts` 的 `stripGenuiPrompt` |
| 存储 | 无。不记录消息 id、会话 id、摘要或时间，也不写 `chrome.storage.local` / `sessionStorage` / 页面属性；刷新后按同一内容规则重新判断 |
| 保守回退 | 正文被改动、只引用首尾标记、校验码缺失或不匹配、以及流式响应无法安全解析时，保留原文，不做猜测性裁剪 |
| 已接受取舍 | 用户把自己消息末尾逐字粘贴完整协议或合法校验码的修复块时也会被移除；这只影响展示，不删除服务端或本地原文，属于不再额外增加复杂度的极端假想场景 |

DOM 侧使用 `removeTrailingCharacters` 跨文本节点裁剪，避免整段重写气泡导致选区或引用丢失。

## 保存记录

一条保存记录包含：

- `stateVersion`：卡片状态结构版本，当前为 1；版本升级后旧记录不再恢复。
- `documentHash`：保存时原始 genui JSON 文本的哈希；原文被改写后不恢复。
- `stateSignature`：协议版本与状态变量结构（类型、取值域、步长、选项）的哈希；结构变化后不恢复。
- `accountId` / `sessionId` / `messageKey` / `duplicateIndex`：保存时的卡片身份，用于跨刷新匹配。
- `savedAt`：保存时间（毫秒时间戳），用于显示恢复时间与容量淘汰。
- `values` / `tables`：已清洗的参数与表格视图（筛选、排序、选中与对比列）。

约束：单条记录 JSON 不超过 32 KB（`MAX_SAVED_STATE_CHARS = 32 * 1024`），状态字段不超过 64 个，表格视图不超过 40 个；最多保留 50 条（`MAX_SAVED_STATES = 50`），超出时删除 `savedAt` 最早的记录。读取时逐字段校验，版本不符、字段缺失、体积异常或身份为空的记录直接丢弃，不做猜测性迁移。

## 身份：怎么判断「还是同一张卡片」

状态键由五段组成，不按标题或 DOM 顺序匹配：

```
card|<状态结构版本>|<账号作用域>|<会话路由>|<消息键>|<同文档重复序号>|<原始文档哈希>
```

- **账号作用域**：读取站点提供的 `data-user-id` / `data-account-id` / `meta[name="user-id"]` 等稳定标记，哈希后使用；缺失时统一为 `acct-unknown`。原始账号 id 不进入键。
- **会话**：只接受 `/a/chat/s/<会话 id>` 形式的路由，去掉末尾斜杠；其他路由一律视为 `unknown-session`。
- **消息**：优先取最近的 `data-virtual-list-item-key`，其次 `data-message-id`；两者都没有时退化为消息文本指纹（不可靠）。
- **重复序号**：同一消息内出现次序；一旦出现完全相同的文档，该序号不再参与区分。
- **文档哈希**：原始 genui JSON 文本的哈希。原文一旦变化就得到新键，旧状态与旧保存记录都不会被套用到新文档。

身份有歧义时（只有文本指纹、同一消息键被多个消息共用、或同一消息内出现完全相同的文档），这些卡片不再共享状态键，改为按 DOM 元素分配一次性键（`amb|<元素令牌>|<文档哈希>`）。同一元素跨扫描保持稳定，但节点替换后即失效；宁可丢失状态，也不让相邻卡片串值。歧义身份不读取保存记录，也不允许保存，点击保存会得到「身份无法可靠确认」的说明。

已挂载卡片每次协调都会按当前账号/会话重新计算身份；路由、会话或账号变化时（含 SPA 复用同一代码块节点且内容不变），旧身份卡片会先撤下并按新会话身份重新挂载，旧状态仍保留在内存中，切回原会话时可恢复。导航变化由适配器 `readNavigationKey` 配合 `popstate`、`hashchange` 与 1 秒轮询发现。

## 恢复与重置

初次挂载时的恢复优先级：

1. 当前页面内的内存状态（同一文档已调整过，或刚被节点替换后重新挂载）。
2. 兼容的本机保存记录：`stateVersion`、`documentHash`、`stateSignature` 三项都相等，且参数重新通过范围/步长/选项校验。
3. 文档初始值。

| 变化 | 行为 |
| --- | --- |
| 同一文档的节点替换、虚拟列表回收后重新挂载 | 身份无歧义时恢复参数、表格筛选与排序；身份有歧义时为元素级键，重新挂载后回到初始值 |
| 原始代码块被改写（哪怕标题相同） | 文档哈希变化 → 新身份；旧内存状态删除，旧保存记录不再匹配，按新文档初始值挂载 |
| 状态结构版本升级 | 旧状态与旧保存记录都不应用；按新文档初始值挂载 |
| 状态变量类型、取值域、步长、选项变化 | 旧值按当前文档重新校验，越界或失效项回落到该字段初始值，其余合法值保留 |
| 表格列变化、排序列不再存在 | 丢弃该排序，筛选文本保留并重新过滤 |
| 刷新页面或重新打开标签页 | 内存清空；若存在兼容保存记录则自动恢复并显示恢复时间，否则回到初始值 |
| 清除本机保存 | 删除该卡片的保存记录；当前界面上的值保持不变，刷新后回到初始值 |
| 卸载扩展 | `chrome.storage.local` 随之清除；已打开页面的注入效果需刷新后消失 |

## 跨刷新匹配与零串值

保存记录优先按完整卡片键匹配。刷新后站点可能更换 `data-virtual-list-item-key`，此时才使用文档级兜底：

- 仅在同一账号、同一会话、同一文档哈希的范围内查找；
- 当前页面上该文档的候选卡片必须恰好一张；
- 匹配到的保存记录也必须恰好一条。

任一条件不满足就不恢复，宁可回到初始值，也不把别的消息的设置串进来。注意 `unknown-session`（非 `/a/chat/s/<id>` 路由）下会话边界较弱，兜底只依赖账号与文档哈希，此时更依赖「唯一匹配」条件；刷新前后消息键不稳定时可能不恢复，这是有意的保守行为。

## 操作与反馈

- **保存当前界面 / 更新已保存的设置**：保存按钮在卡片底部；已有保存记录时文案切换为更新。保存内容来自点击瞬间的同一份状态快照，成功后提示「已保存到本机，刷新后可恢复。」；若因容量清理了旧记录，附注「超出容量上限，已清理最早 N 条保存。」
- **清除保存**：仅在有保存记录时出现。成功后提示「已清除本机保存的设置；当前界面保持不变。」当前界面的值与筛选不受影响。
- **恢复提示**：发生了本机恢复时，卡片顶部显示「已恢复 MM-DD HH:mm 保存的设置；之后的调整不会自动保存。」恢复后继续调整只更新页面内状态，避免每次拖动都写存储。
- **失败反馈**：身份不可靠、环境无存储 API、存储配额不足或写入失败都有固定文案。配额错误显示「本机存储空间不足（QUOTA_BYTES）」；保存失败会回滚内存副本，界面仍可继续操作。
- **重置当前界面**：恢复初始参数并清空筛选，回到初始排序；只影响当前卡片，不删除本机保存。
- 保存与清除都只由用户点击触发；输入、拖动、筛选不会自动写入 `chrome.storage.local`。开关状态仍由唯一的 `genuiEnabled` 键保存。

## 边界与已知限制

- 页面内状态只存在于当前标签页；本机保存只在本机、本浏览器配置文件内，不跨设备同步。
- 保存以卡片为单位，不保存对话文本、草稿或诊断记录，也不改变对话上下文。
- 若文档原文在刷新前后被改写、状态变量结构变化或消息键不稳定且页面存在同文档重复回答，保存不会被恢复；这是零串值约束的代价。
- 存储空间不足时保存可能失败，扩展不会自动清理其他键或降级为页面内保存。
- 依赖 DeepSeek 当前页面结构；站点改版可能影响消息标记、会话路由或挂载，进而影响状态恢复。
