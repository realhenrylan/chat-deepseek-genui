# 卡片状态保存与恢复

本文说明交互卡片的状态在页面内如何保持、`保存方案` 会写入什么，以及刷新、重新挂载、文档改写和切换会话时的恢复与重置规则。实现对应 issue #2，相关代码在 `src/runtime/card-state.ts`、`src/content/identity.ts`、`src/content/plan-store.ts`、`src/content/enhance.ts` 与 `src/render/Card.tsx`。

## 一句话结论

- 页面内：调整过的参数、表格筛选与排序自动保存在当前标签页内存中，生成新回答、同一文档的节点替换或重新挂载不会回到初始值。
- 刷新后：默认不恢复；只有你点击卡片上的 **保存方案**，必要的状态字段才会写入本机 `chrome.storage.local`，下次打开同一会话、同一消息、同一文档时恢复。
- 跨会话/跨消息：不会串用。身份不可靠时只做页面内恢复，并拒绝写入本机。
- 保存方案不会让模型知道你当前的选择；需要把条件带回对话时，使用「继续讨论」生成的摘要并自行发送。

## 两层状态

| 层 | 触发 | 存放位置 | 生命周期 |
| --- | --- | --- | --- |
| 页面内状态 | 调整参数、筛选、排序时自动写入 | 内容脚本内存（每个会话最多 200 张卡片，按最近使用淘汰） | 当前标签页；刷新或关闭页面即丢失 |
| 保存的方案 | 仅点击「保存方案」时写入 | `chrome.storage.local`，每个方案一个键 | 直到你点击「清除保存」、卸载扩展，或超出容量被清理 |

页面内状态优先于保存的方案：刷新后首次渲染会先查找保存记录，之后的所有调整只更新内存；要更新本机记录必须再次点击「保存方案」（按钮会显示「更新保存的方案」）。

## 身份：怎么判断「还是同一张卡片」

状态键由四段组成，不按标题或 DOM 顺序匹配：

```
card|<状态结构版本>|<会话路由>|<消息键>|<同文档重复序号>|<原始文档哈希>
```

- **会话**：当前页面的 `location.pathname`（生产为 `/a/chat/s/<会话 id>`），去掉末尾斜杠；无法读取时为 `unknown-session`。
- **消息**：优先取最近的 `data-virtual-list-item-key`，其次 `data-message-id`；两者都没有时退化为消息文本指纹（不可靠）。
- **重复序号**：同一消息内原始文本完全相同的卡片依次编号，避免前面增删其他 genui 块导致序号整体漂移。
- **文档哈希**：原始 genui JSON 文本的哈希。原文一旦变化就得到新键，旧状态不会被套用到新文档。

以下情况标记为「身份不可靠」：会话未知、只有文本指纹、同一消息键被多个消息共用。此时页面内恢复仍然可用，但拒绝写入本机保存，并提示「当前会话或消息身份无法可靠确认，未保存到本机」。

## 兼容、迁移与重置

| 变化 | 行为 |
| --- | --- |
| 同一文档的节点替换、虚拟列表回收后重新挂载 | 身份不变，恢复参数、表格筛选与排序 |
| 原始代码块被改写（哪怕标题相同） | 文档哈希变化 → 新身份；旧内存状态删除，按新文档初始值挂载 |
| 状态结构版本升级 | 旧保存记录不再兼容，不应用；按新文档初始值挂载 |
| 状态变量类型、取值域、步长、选项变化 | `stateSignature` 不一致，保存记录不应用 |
| 保存记录中的值越界、不符合步长或已不在选项中 | 逐项清洗：回落到该字段初始值，其余合法字段保留 |
| 表格列变化、排序列不再存在 | 丢弃该排序，筛选文本保留并重新过滤 |
| 多会话、多消息、相同标题 | 身份不同，互不串值 |

没有自动迁移：不兼容的旧记录不会强行套用，也不会删除；它们不会被另一份文档使用，并会在容量清理时按保存时间从旧到新淘汰。

## 保存记录里有什么

每个方案一条 `chrome.storage.local` 记录，键为 `genuiPlan:<卡片身份>`，内容仅包含恢复所必需的数据：

- 状态结构版本、文档哈希、状态定义签名；
- 会话路由、消息键、同文档重复序号、保存时间；
- 各状态变量的当前值（数字或选项值）；
- 每张表格的筛选文本与排序列/方向。

不保存聊天正文、AI 回复全文、标题、用户草稿、账号信息，也不发起网络请求或云同步。保存上限为 50 条；单条记录超过 32 KiB 或存储配额不足时会返回明确的失败提示，页面内状态不受影响。

## 操作与反馈

- **保存方案**：写入或更新当前卡片的本机记录；成功提示「已保存到本机，刷新后可恢复。」，若因容量清理了旧记录会补充清理数量。
- **清除保存**：只删除当前卡片的本机记录，内存中的当前调整保持不变；成功提示「已清除本机保存的方案。」。
- **重置当前界面**：恢复初始参数并清空筛选，回到初始排序；不会自动删除已保存的方案。
- 存储不可用（例如无 `storage` 权限的测试环境）时不显示保存入口；保存/清除失败会在卡片底部以 `role="status"` 文案说明原因。

## 边界与已知限制

- 页面内状态只存在于当前标签页，刷新、关闭标签页或卸载扩展后消失；跨设备不同步。
- 刷新恢复依赖站点提供稳定的消息标记（`data-virtual-list-item-key` 或 `data-message-id`）。站点改版或虚拟列表键在刷新后变化时，保存记录不会被错误套用，但可能无法恢复；这需要在真实页面复核。
- 保存方案只恢复界面状态，不改变对话上下文；模型不会自动知道当前选择。
- 同一卡片被改写后，旧的保存记录不会被新文档使用；它可能在容量上限内暂时保留，直到被覆盖或随容量清理淘汰。
- 清除入口针对当前卡片；其他会话或已被删除消息的保存记录只能等容量清理，或卸载扩展时一并清除。
