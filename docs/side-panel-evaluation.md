# 侧栏承载评估（issue #9）

> 状态：方案评审稿，2026-11-04。**本轮只评估，不实现，不新增权限或存储。** 文中凡涉及权限、后台脚本与持久化，均为实施前必须重新评审的草案，不代表当前版本行为。

## 背景

当前增强结果全部承载在聊天流内的卡片里：卡片紧跟 `genui` 代码块，适合「看当前这一步、调参数、把条件带回对话」。issue #9 指出两个长期问题：

1. 站点改版或延迟渲染会同时影响识别、渲染与交互，页面适配需要独立演进；
2. 聊天内空间不适合承载长期的东西，例如多方案并排比较、可复用的工具或已保存方案。

因此先评估「聊天内简洁卡片 + 用户主动打开的侧栏」是否值得做，以及做之前要满足哪些条件。页面适配接口与本地诊断已在本轮落地，见 [站点适配接口与本地诊断](#与本次改动的关系)。

## 目标与非目标

**目标**

- 内联卡片保持「简洁、贴着回答」的定位，不因为长期能力而变重；
- 为多方案比较、已保存工具提供更大的展示面；
- 侧栏与内联共享同一份方案状态，且不会串会话、串标签页。

**非目标（本轮）**

- 不实现侧栏、不申请 `sidePanel` 权限、不新增 service worker；
- 不做跨设备同步、账号体系或云端存储；
- 不把聊天原文、草稿或账号信息复制到侧栏；
- 不改变「无网络 API」的既有不变量。

## 约束与现状

| 约束 | 现状 | 对侧栏的影响 |
| --- | --- | --- |
| 内容脚本范围 | 仅 `https://chat.deepseek.com/*` | 侧栏是扩展页面（`chrome-extension://`），不是站点 DOM，需要跨上下文通信 |
| 网络不变量 | 源码无网络 API，构建期校验 | 只允许本地扩展消息与页面内存；不得引入任何远程加载 |
| 权限 | 仅 `storage` | 侧栏需要 `sidePanel`；主动打开在部分版本还需要后台脚本配合 |
| 后台 | 无 service worker | Side Panel 的推荐入口通常依赖 service worker 的 `setPanelBehavior` / `open` |
| 状态 | 卡片状态仅页面内存，刷新即丢 | 侧栏要显示「当前会话的方案」就必须在页面上下文持有事实来源，侧栏只做只读/操作代理 |
| 身份 | 账号作用域 + 会话路由 + 消息键 + 文档哈希 | 侧栏必须沿用同一身份，不能按标签或标题匹配 |
| 隐私 | 不存储聊天、草稿、账号 | 方案快照可含参数与选项；保存工具会引入用户数据持久化，需要单独评审 |

## 候选方案

### A. 仅内联（基线）

保持现状：所有交互在聊天流内完成，多方案比较用卡片内的候选表或「继续讨论」摘要。

- 优点：零新权限、零后台、隐私与发布口径不变；页面适配与诊断的收益已经拿到。
- 缺点：多方案并排、已保存工具没有合适空间；长列表在聊天流里会打断阅读。

### B. 内联 + 用户主动打开的侧栏（建议评估方向）

内联卡片仍是默认入口与事实来源；用户在需要比较或管理时，显式打开侧栏。

- 优点：日常路径不变；长期能力按需出现；侧栏可以承载并排比较与工具库。
- 成本：新增 `sidePanel` 权限、可能新增 background service worker、扩展页面与内容脚本之间的消息通道、方案模型的提取与测试。
- 风险：跨上下文状态同步、会话切换时的清理、扩展页面与站点主题的一致性。

### C. 仅侧栏

把所有交互搬到侧栏，聊天流内只留「打开面板」入口。

- 不推荐：破坏「贴着回答看结果」的即时性；用户需要来回切换；离线/不支持 Side Panel 的浏览器直接失去核心体验。

## 方案 B 的交互与数据流草案

### 入口

- 浮标新增「方案面板」按钮，仅在 `chrome.sidePanel` 可用且用户点击时打开；不自动弹出，不抢占焦点。
- 浏览器不支持 Side Panel 或调用失败时，按钮不出现或提示「当前浏览器不支持侧栏」，内联能力不受影响（内联回退）。

### 共享状态

- 事实来源：当前标签页内容脚本内的方案仓库（与卡片状态同一套身份：账号作用域 + 会话路由 + 消息键 + 文档哈希）。
- 侧栏通过 `chrome.runtime` 端口向当前标签页请求快照与订阅变更；所有写入（改名、删除、选择对比项）回传到页面仓库，再由页面广播。
- 侧栏不直接读站点 DOM，也不缓存聊天原文；方案标签使用「方案 A / 方案 B」或用户自定义名称，不从聊天内容截取。
- 页面刷新、关闭标签页或卸载扩展后，侧栏显示空态；不尝试从历史恢复。

### 会话隔离

- 侧栏绑定 `tabId` + 会话身份；路由从 `/a/chat/s/<id>` 变为其他会话时，侧栏清空并显示「已切换会话」。
- 同一浏览器多标签页各自独立；侧栏一次只服务发起它的标签页，不做跨标签聚合。
- 身份无法确定（`unknown-session` 或账号标记缺失）时，侧栏只显示当前文档内方案，不提供「保存」入口。

### 已保存工具（需单独决策）

- 「保存工具」意味着把用户定义的参数、选项与名称写入 `chrome.storage.local`，属于新的持久化行为。
- 若实施：仅保存工具定义，不保存聊天原文、完整草稿或账号；提供逐项删除与全部清除；在隐私说明中新增数据行；存储键与容量上限单独评审。
- 该能力**不随侧栏一起默认开启**；没有明确产品决定前不做。

## 权限、平台与生命周期

| 项目 | 草案 | 说明 |
| --- | --- | --- |
| `sidePanel` | 新增，仅实施时申请 | 商店审核需要权限用途说明；README、隐私说明、商店材料同步更新 |
| `side_panel.default_path` | 新增扩展页面 | 本地打包 HTML/JS/CSS，不加载远程资源 |
| background service worker | 可能新增 | 用于 `setPanelBehavior` / `open` 与端口转发；MV3 会被随时终止，**不得把方案状态放在 SW 内存** |
| 最低版本 | Chrome / Edge 114+（Side Panel API）；`sidePanel.open()` 的用户手势路径按 116+ 评估 | 更低版本回退到内联；Firefox 无 Side Panel，保持内联 |
| 打开时机 | 仅用户手势 | 不自动打开，不在页面加载时弹窗 |
| 远程逻辑 | 不允许 | 侧栏页面与内容脚本都只运行本地打包代码，符合 MV3 远程代码政策 |

Service worker 生命周期要点：SW 随时可能被终止，侧栏打开期间也不能假设它常驻；端口断开后由侧栏重新连接并重新请求快照，状态以页面仓库为准。若页面已关闭，侧栏只能显示空态。

## 隐私与发布影响

- 侧栏本身不引入网络请求；方案快照只在扩展进程与本标签页之间传递。
- 若只做「当前会话的方案比较」：不新增持久化，隐私说明只需说明侧栏读取当前页面内存中的方案快照、用户主动打开、不上传。
- 若做「已保存工具」：新增 `chrome.storage.local` 数据类别，必须更新隐私说明、README、商店权限说明与隐私政策链接，并提供删除入口。
- 无论哪种，诊断导出仍只含固定代码、计数与适配器探针，不含聊天、草稿、账号或会话 id。
- 新增权限会触发商店重新审核；发布材料（`docs/store-submission.md`）需要同步权限表与审核步骤。

## 评估结论

1. **方向采纳 B，但不在本轮实施。** 先把方案模型从卡片渲染中抽出来（纯数据 + 本地操作），再评估侧栏；否则侧栏会复制一套 DOM 依赖。
2. **C 不采纳**：牺牲即时性与兼容性，收益不足以抵消。
3. **A 始终是回退路径**：Side Panel 不可用、调用失败或用户关闭时，内联功能完整保留。
4. **实施前置条件**：
   - 方案仓库与身份模块可在无 DOM 环境下测试；
   - 侧栏与内联共享同一方案 id，且会话切换有明确清理用例；
   - `sidePanel` 权限、service worker 与隐私材料完成评审；
   - 至少一条真实 DeepSeek 页面的人工复核记录。
5. **本轮交付**：本评审稿 + 站点适配接口 + 本地脱敏诊断 + 页面变体回归样本；不改 manifest。

## 待评审问题

1. 「已保存工具」是否需要持久化？若需要，保存范围（仅参数模板 / 含选项与名称）与删除交互是什么？
2. 侧栏只服务当前标签页，还是允许固定某个会话？后者会引入跨标签状态，建议先不做。
3. 多方案比较的上限（2 个并排 / 4 个列表）与窄窗口布局？
4. 是否接受为 Side Panel 新增 service worker？若否，可只做「内联 + 新标签页的本地报告页」，但那不是侧栏。
5. 最低支持版本与不支持时的提示文案？

## 与本次改动的关系

本轮已完成页面适配与诊断的分离，为侧栏评估提供稳定边界：

- 站点识别集中在 `src/content/site-adapter.ts`，渲染、状态与计算不再直接依赖站点选择器；
- 本地诊断在 `src/runtime/diagnostics.ts`，只记录类别、代码、计数与探针布尔/数字，用户主动预览、复制或下载；
- 页面变体与延迟渲染样本在 `tests/fixtures/site-variants/`，见 [兼容性调查](compatibility-investigation.md)。

侧栏若实施，应复用同一适配器与身份模块，而不是重新写一套选择器。
