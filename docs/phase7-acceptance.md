## 环境与方法

- 浏览器：Microsoft Edge 156.0.4314.50（Windows 11），加载本仓库 `dist/` 的解压缩扩展；扩展版本 0.1.0，页面右侧显示「GenUI 已开启」。

- 模型：DeepSeek 网页版。页面未暴露可记录的模型版本号，故不填写具体模型名。
- 提示词：场景 1、场景 3 与首次场景 2 使用 v1；场景 2 修复后重跑、同类新问题和不适用问题使用 v2。v2 的逐字文本与版本历史见 [prompt.md](prompt.md)，实现源为 `src/content/prompt.ts`。
- 真实输出均先经过页面实际显示与交互检查；没有把本地 `docs/examples/` 的示例当作模型输出。

## 场景 1：二次函数抛物线学习

用户输入：

> 我想学习二次函数抛物线，帮我做一个可以调 a、b、c 的交互式学习界面

草稿在追加后包含用户原文、`〔GenUI 增强 v1｜…〕` 与完整 v1 提示词，未自动发送。按下 Enter 后，模型先给出文字讲解，约 51 秒后输出一个 `genui` v3 块并挂载为卡片。

- 卡片标题：`二次函数 y = ax² + bx + c 交互探究`
- 初始状态：a=1、b=0、c=-4
- 初始显示：对称轴 x=0，顶点 y=-4，判别式 Δ=16；表格 `-2:0, -1:-3, 0:-4, 1:-3, 2:0`；说明「Δ > 0：与 x 轴有 2 个交点…」；图表范围 -6..23
- 脚注：`透明增强 · 纯文本渲染 · 不执行脚本 · 原始 12423 字符`

交互检查：

- 在 a 滑块上按 ArrowRight，a 从 1 变为 1.5；卡片立即重算为对称轴 x=0、顶点 y=-4、Δ=24、图表范围 -7..36.5，表格变为 `-2:2, -1:-2.5, 0:-4, 1:-2.5, 2:2`。
- 点击「重置当前界面」后恢复 a=1、b=0、c=-4、Δ=16、图表范围 -6..23 与初始表格。
- 点击「继续讨论」后，聊天输入框被填入当前标题与条件摘要，并在末尾追加了完整 v1 提示词；没有发送，摘要与草稿均可在输入框中查看。

结论：真实模型能够按提示词生成可用的 v3 界面，派生值、图表、表格与说明共享同一状态快照，重置和继续讨论符合阶段 6 的设计。

## 场景 2：5000 元笔记本选购对比

用户输入：

> 帮我做一个笔记本电脑选购对比界面：预算 5000 元左右，主要办公和看视频，用表格对比 3 款，并让我能按预算和重量筛选。

### 首次运行（v1，失败）

模型进行了网页搜索并给出文字比较，随后输出一个 4146 字符的 `genui` v3 块。页面没有挂载卡片，原始代码块保持可见，扩展把它标记为 `data-genui-state="failed"`、`data-genui-reason="schema-violation"`。

控制台记录（前 5 条，原样）：

```text
[dsgenui] block skipped (schema-violation): /[/state] must NOT have additional properties;
/[/derived] must NOT have additional properties; /version must be equal to constant;
/elements/1 must have required property 'value'; /elements/1[/bind] must NOT have additional properties
```

这些前 5 条主要是 Ajv `oneOf` 的 v1/v2 分支噪音。把原始块取出后用构建期校验器复现，真正的 v3 错误是：

```text
/elements/3/initialSort must have required property 'dir'
/elements/3/initialSort[/direction] must NOT have additional properties
```

模型写的是：

```json
"initialSort": { "key": "price", "direction": "asc" }
```

而 `src/protocol/schema.ts` 只接受 `{ "key": "...", "dir": "asc|desc" }`。根因是 v1 提示词只在 table 行写了 `"initialSort"?`，没有给出字段形状，模型合理地猜了 `direction`；这不是渲染器错误，也不是模型输出损坏。

该失败暴露了两个需要记录的限制：v1 提示词规格不完整；`formatErrors` 只保留前 5 条 `oneOf` 分支错误，真正原因可能被根级噪音遮住。修复选择是补全提示词并升级到 v2，而不是在协议中增加非标准别名；错误详情排序实验因会破坏既有 detail 断言且 `discriminator` 与图表分支冲突而回退。

### v2 重跑（成功）

同一提示词在 v2 下重跑。模型调用搜索（45 个网页、39 个网页，浏览 8 页）后给出文字比较，并生成了一个有效的 v3 块。卡片标题：

`GenUI 5000元办公本对比（预算/重量筛选）`

- 控件：预算上限滑块 5000 元、重量上限滑块 1.5 kg、筛选表格搜索框
- 表格列：机型 / 参考价 / 重量 / 屏幕 / 处理器 / 电池续航 / 适合场景
- 3 行：
  - 机械革命 无界14 2026：4164 元，1.0 kg
  - 华硕 无畏14SE 2026：3994 元，1.29 kg
  - 荣耀 X14 2026 战斗版：4299 元，1.39 kg
- 脚注：`透明增强 · 纯文本渲染 · 不执行脚本 · 原始 4800 字符`

筛选与重置检查（通过卡片 Shadow DOM 的原生 range `input` 事件触发；场景 1 已单独验证真实键盘 ArrowRight）：

- 预算上限调至 4000：只剩华硕 3994 元一行，状态「显示 1 / 1 行」。
- 预算 5000、重量上限调至 1.2：只剩机械革命 1.0 kg 一行，状态「显示 1 / 1 行」。
- 恢复预算 5000、重量 1.5：3 行全部显示，状态「显示 3 / 3 行」。
- 点击「重置当前界面」：恢复 5000 元 / 1.5 kg / 3 行。

流式生成期间曾出现一次瞬时 `invalid-json`（`Unterminated string in JSON at position 9`），当时块尚未输出完；回答结束后重新同步，卡片已挂载、块状态为 `mounted`。这是流式不完整块的正常等待行为，不是持久失败。

另有一个与模型无关的站点行为需要说明：DeepSeek 对不在视口内的代码块采用延迟渲染，离屏时 DOM 中只有代码块头部和极短前缀，扩展因此会看到不完整的 JSON；滚动到代码块后站点补齐完整文本，扩展随后正常挂载。验收中的第一个健身房复杂回答与场景 2 的部分读取都受此影响，滚动/等待后均恢复，不应误记为模型生成失败。

## 场景 3：每月预算分配工具

用户输入：

> 做一个每月预算分配工具，让我调整各项支出并看到余额

卡片标题：`每月预算分配器`。

- 7 个滑块：住房 3500、餐饮 2500、交通 600、水电 500、娱乐 1200、其他 400、储蓄 2000（元）
- 初始汇总：总分配 10700 元，每月余额 1300 元，储蓄率 17%
- 表格：预算表 8 行（含收入与合计），另有图表数据表；脚注 `原始 8568 字符`
- 模型正文同时给出 50/30/20 参考、示例估算与调整顺序。

交互检查：

- 住房从 3500 调到 4000：总分配 11200 元，余额 800 元；预算表住房行 4000 元 / 33%，合计 93%。
- 住房从 4000 调到 30000：总分配 37200 元，余额 -25200 元；页面显示警告「分配已超过收入：余额为负，请下调娱乐购物或其他弹性项，或降低储蓄目标。」，住房行 250%，合计 310%。
- 点击「重置当前界面」：恢复住房 3500、总分配 10700、余额 1300。

结论：条件说明、汇总值、图表与表格由同一状态快照驱动，超支回退可见且可恢复。

## 同类新问题：健身房会员卡

### 简单版（v2）

用户输入：

> 做一个简单的健身房会员卡对比：月卡 299 元、季卡 799 元、年卡 2599 元，每月去 8 次。只要一个可调每月次数的滑块和一个三行对比表，显示每次成本即可，不要图表。

模型给出公式与文字结论，生成的卡片标题为 `GenUI 健身房会员卡每次成本对比`。

- 初始每月 8 次：月卡 299 / 8 次 / 37.38 元/次；季卡 799 / 24 次 / 33.29 元/次；年卡 2599 / 96 次 / 27.07 元/次
- 把滑块调到 12 次/月：月卡 24.92 元/次、季卡 22.19 元/次、年卡 18.05 元/次；总次数 12 / 36 / 144；状态「12 次/月」「显示 3 / 3 行」
- 脚注 `原始 3491 字符`

### 复杂版（v2）

第一次复杂提问额外要求“计划坚持几个月”的维度。模型输出包含两个滑块：

- 每月去几次（8）与计划坚持几个月（12）
- 每次成本：37.38 / 33.29 / 27.07 元/次
- 计划期总支出：月卡 3588、季卡 3196、年卡 2599 元；总次数 96
- 把坚持月数调到 9：月卡 2691、季卡 2397、年卡 2599 元；总次数 72；每次成本不变

这验证了 `ceil` 月数派生与总支出联动，而不是只有静态换算。

## 不适用问题：普通事实问答

用户输入：

> 水的沸点是多少？在标准大气压下。

模型只给出文字回答：100 °C / 212 °F / 373.15 K（1 atm，101.325 kPa），并补充海拔/气压和溶质影响的说明；没有生成 `genui` 块或卡片。模型思考中明确出现「简单事实问答，不需要 genui」。这与提示词的“适合时才生成、普通问题正常回答”一致。

## 默认增强的行为验收

- **可见追加**：输入普通问题后等待 700ms，草稿末尾出现 v1/v2 起始标记、完整协议说明和结束标记；发送前可逐字阅读。没有隐藏消息、没有自动发送。
- **已有草稿保护**：在已有文字后再输入时，追加只发生在末尾；关闭开关只移除仍完整的尾部自动说明，保留用户原文。测试 `阶段7关闭测试` 时，textarea 在关闭后恢复为完全一致的 `阶段7关闭测试`。
- **去重与重新开启**：草稿已含标记时不重复追加；关闭后重新开启，会对当前非空草稿重新追加。
- **手动删除**：用户删除说明文本后，当前草稿不再自动追加；清空草稿后恢复可追加状态。
- **面板可核对**：点击「查看增强说明」打开 `GenUI 增强说明 v2` 对话框；面板明确说明“下面这段文本会逐字追加在你输入框草稿的末尾……扩展不会自动发送消息，也不使用隐藏消息”，并以 `<pre>` 展示同一条 `GENUI_PROMPT_TEXT`。草稿为空时状态为「等待输入」，卡片页显示「已追加到当前草稿」。
- **关闭后的原始内容**：关闭开关会把卡片卸下、恢复原始代码块显示；文字回答仍可阅读，不依赖卡片。

## 协议合法性、操作正确性与安全复查

- 场景 1、场景 2（v2）、场景 3、两个健身房版本均通过 v3 Schema 与语义校验并挂载；场景 2 的 v1 块是唯一的持久失败，已定位到提示词字段形状缺口并在 v2 修复。
- 本地交互验证覆盖：滑块键盘与原生输入、数值派生、条件说明、表格筛选与空行状态、图表数据更新、重置、继续讨论。所有计算在卡片 Shadow DOM 内由本地白名单表达式执行，不依赖网络或模型二次调用。
- 扩展不执行生成的 HTML/CSS/JavaScript；代码块按纯文本读取，渲染器只接受协议字段，未知/非法内容回退为原始文本。`manifest.json` 仅申请 `storage`，无 `host_permissions`、无后台脚本。
- `tests/unit/extension-static.test.ts` 检查 `src/` 源码不含 `fetch`、XHR、`sendBeacon`、WebSocket、`EventSource` 等网络 API；`npm run build` 的 `check-dist` 扫描产物中的 `eval`/`new Function`/`importScripts`/远程脚本与样式 URL/CDN，违规则构建失败。真实页面没有做 URL 级网络归因（见限制），因此本记录不声称“URL 级零请求”，只声称源码静态不变量、权限清单、构建扫描和模拟页零请求断言四个维度。
- 生成的卡片脚注固定显示「透明增强 · 纯文本渲染 · 不执行脚本」，提示用户这是本地解释结果。

## 失败案例与限制

1. **v1 场景 2 失败**：`initialSort.direction` 不符合协议；修复为 v2 提示词明确 `{key, dir}`。没有放宽协议接受 `direction`，避免协议出现两套字段名。
2. **离屏代码块延迟渲染**：站点只有在代码块进入视口后才补齐完整文本；扩展在补齐前会看到短前缀并暂时标记失败。滚动后自动恢复。这是站点行为，扩展无法在文本尚未进入 DOM 时验证完整 JSON；验收时按“滚动到回答末尾”的正常阅读路径操作。**缓解已落地（验收后）**：生产内容脚本新增视口门控（`src/content/viewport-gate.ts` + `EnhanceOptions.isBlockUnverifiable`），块首次进入视口之前的解析失败不再写入 `data-genui-state="failed"`，而是延迟到可验证后重新判定（控制台输出 `block deferred (offscreen)`）；单元测试覆盖适配器、失败出口与生命周期接线（`tests/unit/viewport-gate.test.ts`）。注意：门控只抑制“失败标记”，文本已完整有效的离屏块仍会正常提前挂载。
3. **流式瞬时 `invalid-json`**：回答尚未结束时扫描到不完整 JSON 属预期；完成后再验证。当前实现不会对仍活跃的生成做最终失败判定。
4. **真实页面网络归因**：没有在本次人工验收中录制页面网络；因此“无未声明网络行为”的证据来自源码零网络 API 静态测试、manifest 权限、构建扫描和模拟页请求断言，而不是真实页面 URL 级抓包。
5. **模型版本未记录**：DeepSeek 网页未暴露模型标识；本记录只记录产品行为，不宣称某一具体模型版本的稳定性。
6. **站点结构依赖**：输入框选择、流式状态、代码块语言标签与离屏渲染均依赖站点当前 DOM；站点改版会导致增强或识别失效，需重新取证。
7. **v2 收尾文字修正**：真实验收后，根对象说明从“`elements` 可为空数组”修正为“`elements` 至少 1 个元素”，以对齐 Schema 的 `minItems: 1`。所有真实验收输出都包含元素，没有触发该分支；本次未因这一约束文字重跑模型。

## 复现步骤

1. `npm run build`，在 Edge `edge://extensions` 重新加载 `dist/`（改代码后必须刷新扩展，否则页面仍运行旧内容脚本）。
2. 打开 `https://chat.deepseek.com/`，确认右侧显示「GenUI 已开启」。
3. 新建对话，输入上述任一用户提示词；等待约 700ms，确认草稿末尾出现可见的 `〔GenUI 增强 v2｜…〕`，并点击「查看增强说明」核对全文。
4. 自行按 Enter 发送；等待回答完成，滚动到回答末尾使代码块完整渲染，确认卡片挂载。
5. 调整滑块/筛选/月数，检查数值、图表、表格与条件说明同步更新；点击重置恢复初始；点击继续讨论检查摘要仅填入输入框、不发送。
6. 关闭增强，确认原始代码块恢复且草稿尾部说明被移除；重新开启确认可再追加。

## 结论
