# issue7 基线与真实任务对照

本文件为 issue7（提示词体验与本轮模式）建立验证基线：先用现有默认自动适配跑通固定任务集并记录指标，再与「明确生成工具」变体对照，最后按结果决定保留或回退。预置变体不承诺未测得的生成成功率；一切结论以真实模型输出为准。

## 目标与原则

- 保持默认「自动适配」逐字节不变；新能力只以显式选择的本轮模式提供，不改变后续会话设置。
- 用户始终能逐字检查实际进入对话的增强内容（浮标面板 `<pre>` 与草稿引用同一常量）；不使用隐藏消息、不自动发送。
- 能力说明与 `src/protocol/schema.ts` 实际支持的 v3 字段、版本、预算一致；tool 变体与 auto 共享协议主体，仅首段表达策略不同。
- 不以缩短字数替代生成可靠性；先建立基线，再对照，不预先承诺提示长度带来的收益。

## 范围界定（先说清楚，再对照）

- 实测字符数（2026-11-04，直接计量 `GENUI_*` 常量）：自动适配 **4189** 字符、「明确生成工具」**4237** 字符、「普通回答」固定说明 **34** 字符；两个变体从「内容分工」起的协议主体 **3971** 字符逐字节共享。
- **tool 变体不是精简方案**：它比默认文本更长的 48 个字符来自更明确的首段表达策略，不是压缩。issue7 已交付的是「本轮模式」能力；真正缩短说明（按能力分组、减少示例等）属于后续工作，须以本文件的对照流程单独验证。
- **「每轮重发」与「只发送一次」的差异未验证**：当前实现每轮都随草稿完整发送说明（自动适配与 tool 均如此，见 `docs/prompt.md` 设计要点），没有任何「只发一次」路径；下方「会话长度对照」设计仍待执行。

## 固定任务集（A/B 同组任务）

| # | 任务原文 | 类型 | 预期形态 |
| --- | --- | --- | --- |
| 1 | 用月收入 12000、固定支出 3500，帮我算每月能存多少，可以自己调调看 | 参数计算/规划 | 界面 + 简短正文 |
| 2 | iPhone 15 Pro 和小米 14 哪个好？ | 对比 | 简短结论 + 对比表 |
| 3 | 画个图帮我理解抛物线 y=x²−4x+3 | 可视化 | 图表（可选 smooth） |
| 4 | 帮我写一封请假条 | 写作 | 仅正文，无 genui |
| 5 | 中国的首都是哪里？ | 事实问答 | 仅正文，无 genui |

每任务至少 3 遍、每个新会话执行一次；auto（组 A）与 tool（组 B）轮流交叉，避免顺序效应。

## 指标

- **首轮可用率**：任务 1–3 采用「首轮输出可被 `parseGenui` 解析且元素形态命中预期」口径；任务 4–5 采用「未生成 genui 界面」口径。两类口径分开统计、分开报告，不用同一把尺子。
- **生成可靠性**：每任务的首轮解析失败、缺拒字段（如 `dir`/`direction`）、超预算等失败例与修复步骤数。
- **提示长度**：追加说明的字符数（auto vs tool）与整条消息长度；正文长度仅记录不设目标。
- **普通问答误触发**：任务 4/5 生成了界面即计 1 次误触发。

## 对照设计

- 组 A = 自动适配（现状默认）；组 B = 浮标点选「明确生成工具」。
- 每组执行同一固定任务集，记录上述指标；差异在同一模型、同一日期、同一网络下测量。
- **会话长度对照**：在同一会话连续执行 7 个任务，记录第 7 个任务的可用率与说明是否仍在草稿中，验证「完整说明必须每轮随草稿发送」的假设（新会话 / 长会话 / 上下文丢失三口径都记录）。
- 对照期间不改任何其他代码；记录模型名称、日期、样本数与全部失败例原文。

## 回退策略

- 变体入口只存在于浮标「本轮」按钮，未持久化；`createToggleControl` 在未提供 tool 文本时自动隐藏该按钮，因此回退=一版内不传 `promptTexts.tool` 或移除按钮，默认体验立即回到 v2.2。
- 保留 tool 变体需同时满足：首轮可用率不低于组 A、普通问答误触发不劣化、提示长度确实缩短且用户可感知。
- 任何一项不满足：在 `docs/phase7-acceptance.md` 记录后回退，并把结论写入 `docs/prompt.md` 版本历史。
